# /build backend <dashboard>

Compiles every widget's recipe through `packages/semantic-query` for every test user, writes the reviewed SQL snapshot, and proves RLS with the two-user test. The snapshot is for humans and CI to read; the portal compiles at runtime.

## Reads
- `dashboards/<name>/spec.yaml`
- `catalog/kpi-registry.yaml`, `security/rls-policies.yaml`
- `security/test-users.yaml`: the users and the `expect` line
- `packages/semantic-query/README.md`: the `compile` signature

## Writes
- `dashboards/<name>/queries.sql`

## Steps
1. Load the spec and take every widget with a non-null `kpi`; load its recipe. `RETIRED` stops the build (below); `DRAFT` is kept and tagged `preview-only`. Done when each widget is listed with recipe id, status and kind.
2. Check every `kind` against the kit map in `docs/contracts/spec.md`. Done when every kind is in the map.
3. For each widget × each user in `security/test-users.yaml`, call `compile({ kpi, user, period, by, filters })` with `period` from the recipe's `compare` window, `by` and page filters from the widget. Done when the number of compiled queries equals widgets × users.
4. Write `dashboards/<name>/queries.sql`: first line `-- GENERATED by /build backend. Compiled SQL per widget per test user, for review. Never executed from here.`, then each query preceded by one comment `-- <widget> · <kpi> · user <id> (<role> → <rule>[: values])`, widget order then user order, shaped like `docs/sample/dashboards/cashboard/queries.sql` (example). Done when the file holds one comment per query and every statement ends with `;`.
5. Two-user test on the read-only replica account: for each recipe whose view's policy has a column, run its compiled queries and check the `expect` line: the two `by_entitlement` users differ, `hq` equals the unfiltered total, `none` returns no rows. Print `recipe · user · rows · value · result`. Done when every restricted recipe has PASS on all three checks.
6. Print the summary: widgets built, preview-only widgets (DRAFT recipes), skipped widgets (BLOCKED, with `needs`), path to `queries.sql`. Done when every widget of the spec appears exactly once.

## Stops when
- A widget's recipe is `RETIRED` → name it; the spec must be rebound (`/spec`).
- A `kind` is outside the kit map → name it; a kit change, not a spec change.
- A widget's view has no entry in `rls-policies.yaml` → "run /rls <view>".
- A two-user check fails → print the failing SQL pair and stop. The fix lives in `rls-policies.yaml` or the entitlements table (`docs/rls.md`), never in the query.
- No read-only account is configured → write `queries.sql`, print the test as SKIPPED, stop. The frontend waits.

## After it
Nothing runs. The user runs `/build frontend <dashboard>` once the two-user test has passed, then `/verify <dashboard>` after the business preview.
