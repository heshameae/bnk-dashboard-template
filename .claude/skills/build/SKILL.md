# /build

Everything on the page comes from `dashboards/<name>/spec.yaml`. The design export is never opened.

## Run it
- `/build backend <dashboard>` → read `backend.md` in this folder and follow it.
- `/build frontend <dashboard>` → read `frontend.md` in this folder and follow it.
- `/build <dashboard>` → backend, then frontend; frontend starts only after the backend's two-user test passed.

## Reads / Writes
Reads `dashboards/<name>/spec.yaml`, `catalog/kpi-registry.yaml`, `security/rls-policies.yaml`, `security/test-users.yaml`, `packages/semantic-query/`. Writes `dashboards/<name>/queries.sql` (backend) and `apps/portal/src/dashboards/<name>/` (frontend).

## Gates shared by both modes
- Spec status is READY, or BLOCKED with the READY widgets built and each blocked widget rendered as a placeholder naming its `needs`.
- The only database access is the read-only two-user test in `backend.md`. Nothing writes to Oracle.
- Every generated file starts with a `GENERATED by /build` header and is regenerated, never edited: a change the business asks for is a spec edit, then a rebuild.

## After it
Nothing runs. The user shares the dev URL with the business, folds every requested change into `spec.yaml`, rebuilds, and then runs `/verify <dashboard>`.
